# 通信约定

本文件约定 agent 之间、agent 与维护者之间的消息写法。原则：结论先行、链接完整、可验证、不刷屏。

## 语言与语气

- 文档、Issue、PR 与消息使用中文；代码、标识符、提交类型使用英文。
- 陈述事实与下一步，不使用空泛的“已处理”“优化了一下”。

## 渠道

| 渠道 | 用途 |
| --- | --- |
| 需求所在会话（Issue / 对话） | 面向维护者的结果、问题与阻断 |
| Issue / PR | 需要长期保留的讨论、证据、评审记录 |
| `.agents/` | 稳定的设计、决策与协作约定 |

过程进展留在内部记录，不单独通知维护者；只有可交付结果、需要人类决定的问题或明确阻断才对外发送。

## 消息类型

| 类型 | 何时使用 | 要点 |
| --- | --- | --- |
| 开始确认 | 接到新需求、开始实质工作前 | 一句话说明要改什么、交付什么 |
| 交接 | 工作转给他人 / 另一个执行者 | 已完成、未完成、验证方式、风险、下一步 |
| 阻断 | 确实无法继续 | 缺什么、为什么本地无法解决、最小所需动作 |
| 评审回复 | 回应评审意见 | 逐条说明已修/不修及原因，不重复旧内容 |
| 完成 | 结果可供使用 | 结果、链接、必要限制与下一步 |

## 文字格式

- 面向维护者的消息尽量一到两句话：结果 + 链接 + 需要对方做的动作。
- 阻断说明使用“现象 → 已尝试 → 最小所需动作”的结构。
- 引用代码、文件、提交时给链接或路径；不复述整段实现。
- 不粘贴私有内容、令牌、个人数据。

## 状态用词

统一使用：`待处理`、`进行中`、`待评审`、`已阻断`、`已完成`、`已合并`、`已关闭`。

## 交接模板

使用 [`templates/handoff.md`](templates/handoff.md)。交接必须能让接手者不看聊天记录也能继续。

## 评审通信

- 对每条意见给出明确结论：已修复、部分修复、不采纳（附理由）。
- 修复并验证后解决对应讨论串；不重复发送“已修复”类评论。
- 不向自动评审工具反复索取批准，也不因自动意见扩大范围。

## 升级

以下情况立即升级：需要产品/视觉决策、需要仓库管理员权限、存在数据或隐私风险、同一问题连续两次修复失败。
